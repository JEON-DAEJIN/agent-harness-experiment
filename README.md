# agent-harness-experiment

AIFFEL N029(에이전트 하네스 톺아보기) 과제 제출 저장소.

논문/교재의 하네스 기능 가설을 실제로 쓰는 도구(Claude Code)에서 직접 실험으로 검증하는 과제입니다. 실험 대상은 오늘 이 세션에서 실제로 겪은 불편(문서 검증 파이프라인에서 Bash 명령이 매번 개별 승인을 받아 흐름이 끊긴 것)입니다.

## 요약 (가설 · 실험 설계 · 결과 · 재검토 조건)

- **가설**: 동일한 검증 작업을 수행할 때, Bash 호출을 사전에 계획해 하나의 배치로 묶어 요청하면(배치 승인 정책) 개별 승인 정책 대비 승인 요청 횟수가 크게 줄어들면서도, 위험해 보이는 명령이 배치 안에 섞여도 승인 시점에 여전히 식별 가능하다(안전성 저하 없음). *반증 조건*: 승인 횟수가 줄지 않거나 위험 명령이 식별 불가능해지면 가설은 틀린 것.
- **실험 설계**: 고정(같은 모델·같은 3개 fixture 과업·같은 도구) / 조작(권한 정책 단 하나 — 개별 승인 vs 배치 승인) / 측정(승인횟수·소요시간·실패횟수·위험명령 식별여부) / 사전 판정식(승인 40%↑ 감소 + 위험명령 식별 + 양쪽 성공 → 지지).
- **결과**: 총 승인 횟수 13회→7회(−46.2%), 총 소요시간 104.5초→61.5초(−41.2%), 실패 0건, 위험-외견 명령(`rm -rf`)은 배치 텍스트 안에서 그대로 식별 가능. → **사전 판정식 기준 가설 지지**. 다만 Bash+Browser 혼합 태스크(verify-html)는 배치가 도구 카테고리를 넘지 못해 개선폭이 17%에 그침 — 계획에 없던 하네스의 구조적 경계로 별도 기록.
- **재검토 조건**: (1) 조건 순서를 교차한 반복 실험, (2) Bash+Browser 혼합 태스크의 승인 절감 방법 탐색, (3) 위험 명령을 더 교묘히 숨겼을 때의 식별 한계선 — 이 중 하나라도 실행되어 다른 방향의 수치가 나오면 이 판정을 재검토한다.
